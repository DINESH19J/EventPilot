## What Is Happening?

Pre-implementation Static Timing Analysis (Pre-STA) evaluates the timing behavior of the synthesized EventPilot design before physical implementation. It checks whether signal paths satisfy the required setup and hold timing constraints.

## Understanding the Process Corners

- **SS (Slow-Slow):** Models slow NMOS and PMOS transistor behavior. It is commonly important for setup timing because slower cells can increase path delays.
- **TT (Typical-Typical):** Models typical NMOS and PMOS transistor behavior according to the selected technology library.
- **FF (Fast-Fast):** Models fast NMOS and PMOS transistor behavior. It can be important for hold timing because data may arrive earlier.

The actual timing results also depend on voltage, temperature, timing constraints, and the selected library models.

## How Is It Implemented?

The STA tool analyzes the synthesized netlist using the appropriate timing constraints and standard-cell timing library.

For each verified process corner, the tool can report:

- Setup slack
- Hold slack
- Data-path delay
- Startpoint and endpoint
- Critical timing paths

The SS, TT, and FF reports must each use the corresponding library and analysis configuration.

## Result and Observation

The Pre-STA reports establish a timing baseline for EventPilot before the later physical-design stages.

Positive setup or hold slack indicates that the analyzed path meets its corresponding timing requirement under the conditions used for that report.

The numerical results should be taken from the actual reports for each verified corner.

## Why Is This Stage Important?

Pre-STA helps identify potential timing problems before physical implementation. Analyzing multiple process corners provides a broader view of the controller's timing behavior.

## What Is Happening?

Post-implementation Static Timing Analysis (Post-STA) evaluates the timing behavior of EventPilot after physical-design implementation.

Depending on the analysis configuration, it can account for physical effects such as placement- or routing-estimated interconnect parasitics.

## Understanding the Process Corners

- **SS (Slow-Slow):** Uses the slow-process timing models from the selected library and is commonly important for setup analysis.
- **TT (Typical-Typical):** Uses the typical-process timing models from the selected library.
- **FF (Fast-Fast):** Uses the fast-process timing models from the selected library and can be important for hold analysis.

These are modeled process conditions, not measurements from a fabricated chip. Voltage, temperature, constraints, and parasitic settings also affect timing.

## How Is It Implemented?

The STA tool evaluates the implemented design using the applicable netlist, timing constraints, and standard-cell libraries.

For a valid multi-corner analysis, each result must be generated using the intended process-corner library and compatible analysis settings.

The reports are examined for setup slack, hold slack, path delay, and critical timing paths.

## Result and Observation

The Post-STA reports describe the timing behavior of the implemented design under their respective analysis conditions.

Setup and hold slack indicate whether the analyzed paths meet their timing requirements. Comparing pre-STA and post-STA can reveal changes associated with physical implementation, provided that the analysis conditions are comparable.

Only verified SS, TT, and FF results should be included in the final comparison.

## Why Is This Stage Important?

Post-STA helps assess timing after physical implementation, when interconnect and other physical effects may influence path delays.
